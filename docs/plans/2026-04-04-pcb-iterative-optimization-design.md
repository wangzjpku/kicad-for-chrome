> 版本: v1.0.0 | 日期: 2026-04-04
> 状态: 已确认

## 一、项目概述

### 1.1 目标
对STM32F103C8T6最小系统板进行迭代优化，通过根本原因分析和方案评审，将设计质量从初始分数提升至89分（A级）或达到20次迭代上限。

### 1.2 核心约束
- **禁止参数游戏**：不允许为了得分而直接修改线宽、间距等参数值
- **必须根因分析**：每个扣分点必须经过3层追问找到设计层面的根本原因
- **方案评审**：每个问题至少提出3个候选方案，选择最优执行
- **过程记录**：完整记录每次迭代的根因分析、方案对比、选择理由

## 三、CAD设计错误检查清单

在每次评分前，先执行基础CAD验证：

### 3.1 原理图基础检查
| 检查项 | 通过标准 |
|--------|----------|
| 网络连通性 | 所有网络至少2个连接点 |
| 电源网络 | VCC/GND连接完整 |
| 元件唯一性 | 无重复reference |
| 引脚匹配 | 符号引脚数=封装焊盘数 |

### 3.2 网表一致性检查
| 检查项 | 通过标准 |
|--------|----------|
| 网络数量 | 原理图网表 = PCB网表 |
| 元件数量 | 原理图元件 = PCB元件 |
| 网络成员 | 每个网络的引脚成员一致 |

### 3.3 封装验证
| 检查项 | 通过标准 |
|--------|----------|
| 封装存在 | 所有footprint在库中存在 |
| 焊盘编号 | 封装焊盘号与符号引脚号对应 |
| 封装方向 | 1号焊盘位置正确 |

### 3.4 布线基础检查
| 检查项 | 通过标准 |
|--------|----------|
| 未连线 | 无悬浮的焊盘/走线端点 |
| 网络短路 | 不同网络无电气连接 |
| 走线层 | 走线在有效铜层上 |
| 过孔连通 | 过孔连接上下层走线 |

### 3.5 错误处理优先级
```
🔴 CAD基础错误 > 🟡 质量评分扣分 > 🟢 优化建议
```

## 四、根本原因分析规则

### 4.1 强制3层追问机制
```
扣分点发现 → 第1层"为什么？" → 第2层"为什么？" → 第3层"为什么？" → 根本原因
```

### 4.2 示例对比
| 层级 | ❌ 错误分析（参数游戏） | ✅ 正确分析（设计根源） |
|------|------------------------|------------------------|
| 扣分点 | 信号完整性8/10分 | 信号完整性8/10分 |
| 第1层 | 线宽不够宽 | USB走线过长 |
| 第2层 | 设计规则设置太小 | MCU与USB接口距离远 |
| 第3层 | *参数游戏结束* | 布局时未考虑高速信号路径 |
| **根本原因** | ~~调大线宽~~ | **布局策略未考虑信号流向** |

### 4.3 禁止的行为
- 直接修改 `min_track_width`、`clearance` 等参数值
- 为了得分而编造不存在的改进
- 跳过3层追问直接给方案

### 4.4 允许的修改
- 移动元件坐标（重新布局）
- 删除并重新布线（改变走线路径）
- 增加/删除过孔
- 调整铜皮形状和位置
- 修改网络连接拓扑

## 五、方案评审与选择机制

### 5.1 方案有效性检查清单
- ☑ 改变的是设计结构（布局/拓扑/连接），而非数值参数
- ☑ 明确说明预期能解决哪些扣分点
- ☑ 评估了可能引入的新问题
- ☑ 说明了具体实施步骤

### 5.2 方案评分维度
| 维度 | 权重 | 评估标准 |
|------|------|----------|
| **有效性** | 40% | 预期分数提升量 |
| **安全性** | 30% | 副作用风险（低=3分，中=2分，高=1分） |
| **效率** | 30% | 实施复杂度（低=3分，中=2分，高=1分） |

### 5.3 选择公式
```
方案得分 = 预期提升 × 0.4 + 安全性得分 × 0.3 + 效率得分 × 0.3
```

### 5.4 修改优先级（必须遵守）
1. 🔴 电气错误 → DRC违规 → 布线完成率
2. 🟡 可制造性问题 → 信号完整性
3. 🟢 热设计 → EMC → 美学

### 5.5 单次迭代限制
最多修改5个独立任务，防止上下文爆炸
