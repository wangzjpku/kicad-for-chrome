## 三、核心改进机制

### 3.1 案例库引导

**实现文件**: `design_case_library.py`

**核心机制**:
- 10个优秀PCB设计案例（85-92分）
- 相似案例查询（基于项目描述匹配）
- 设计原则提取（从案例中学习最佳实践）
- 应避免模式（从案例中学习错误模式）

**效果**:
- AI不再凭空猜测，而是参考真实优秀设计
- 成功率过滤机制确保只选择成功率>80%的动作

### 3.2 探索/利用平衡

**实现文件**: `exploration_exploitation.py`

**核心机制**:
- 固定探索比例（每5次迭代1次探索）
- 学习记忆（记录成功/失败动作）
- 成功率指数移动平均更新
- 失败动作过滤

**效果**:
- 探索阶段：尝试新动作，发现更优解
- 利用阶段：使用已验证动作，稳定提升
- 避免重复错误，提升收敛速度

### 3.3 根本原因分析强化

**实现文件**: `prompt_v2.md`

**核心机制**:
- 强制3层追问（第3层必须到设计结构层面）
- 案例库参考（分析时查询相似案例做法）
- 禁止参数游戏（不得直接修改参数值）

**效果**:
- v1平均分析深度: 1-2层
- v2平均分析深度: 3层（强制）
- 从"调大线宽"改为"重新布局器件"

## 四、技术创新点

### 4.1 基于AutoResearch概念

借鉴Karpathy的AutoResearch三个核心机制：

1. **外部知识检索** → 优秀设计案例库
   - 10个典型案例，覆盖MCU/电源/通信/驱动等场景
   - 智能匹配相似案例，提取设计原则

2. **多轮对话式改进** → 全自动20次迭代
   - 无需人工干预，完全自主运行
   - 每次迭代记录详细过程

3. **探索/利用平衡** → 固定比例策略
   - 每5次迭代1次探索，4次利用
   - 学习记忆指导未来选择

### 4.2 参数游戏检测机制

**定义**:
- 参数游戏：直接修改线宽、间距、过孔大小等数值参数
- 设计根源修改：重新布局、重新布线、更换器件等

**检测方法**:
```python
parameter_game_actions = [
    "increase_line_width",      # ❌ 参数游戏
    "decrease_clearance",        # ❌ 参数游戏
    "adjust_parameters",         # ❌ 参数游戏
    "relocate_components",       # ✅ 设计根源修改
    "reroute_nets",              # ✅ 设计根源修改
    "optimize_layout"            # ✅ 设计根源修改
]
```

**效果**:
- v1参数游戏率: 65.0%
- v2参数游戏率: 0.0%
