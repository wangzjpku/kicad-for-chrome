# 视觉Ralph Loop迭代测试 - 可执行提示词

## 复制以下完整内容粘贴到 Claude Code 执行

---

## 完整提示词

```
请执行 视觉Ralph Loop 多模态迭代测试流程，对AI生成的原理图和PCB进行全面验证和修复。

## 核心目标
使用多模态验证（数据+规则+视觉+语义）迭代修复所有问题，直到达到发布质量标准。

## Ralph Loop 配置
- 最大迭代: 20次
- 收敛条件: ERROR = 0, WARNING <= 3
- 每次迭代必须执行完整验证流程

## 多模态验证框架

### Layer 1: 数据层验证 (Netlist Deep Analysis)
- 解析 .kicad_sch 和 .kicad_pcb 文件
- 对比原理图网表和PCB网表一致性
- 检查网络节点数量、连接完整性
- 检测缺失网络和多余网络

### Layer 2: 规则层验证 (DRC/ERC)
- 运行 KiCad DRC 检查
- 运行 KiCad ERC 检查
- 自定义设计规则验证
- 电源网络完整性检查

### Layer 3: 视觉层验证 (Visual AI Analysis)
- 导出原理图和PCB的SVG/PNG截图
- 使用视觉AI分析截图
- 检测连线是否真正到达引脚端点
- 检测网络标签位置是否正确
- 检测元件布局是否合理

### Layer 4: 语义层验证 (Functional Analysis)
- 电路功能正确性分析
- 信号流向合理性
- 元件选型合理性
- 数据手册一致性

## 迭代工作流

### 第1次迭代 (初始化)
1. 创建截图目录: screenshots/iter1/
2. 生成初始截图
3. 执行所有4层验证
4. 生成 问题.md (初始问题清单)
5. 分析问题根因
6. 执行优先级最高的修复

### 第2-20次迭代 (迭代修复)
每次迭代执行:
1. 创建截图目录: screenshots/iter{N}/
2. 生成当前状态截图
3. 执行4层验证
4. 对比上次结果，识别:
   - 已修复问题 (fixed)
   - 新增问题 (new)
   - 剩余问题 (remaining)
5. 更新 问题.md (添加迭代记录)
6. 分析未修复问题的根因
7. 执行修复
8. 检查收敛条件

## 视觉验证提示词 (用于图像分析)

当需要分析截图时，使用以下提示词:

```
分析这张KiCad原理图/PCB截图，检测以下问题:

## 连接端点检测
- 检查每条连线的终点是否在元件引脚的中心位置
- 标记未到达端点的连线 (连线终点距离引脚中心>5像素)
- 检测悬空连线 (两端都没有连接到任何引脚)

## 网络标签检测
- 检查网络标签是否放置在连线上
- 检查网络标签文字是否清晰可读
- 检查是否有遗漏的网络标签

## 元件检测
- 检查元件符号/封装是否正确显示
- 检查元件参考编号是否清晰
- 检查元件值是否标注

## 输出格式
{
  "connection_issues": [
    {"wire_id": "W1", "from": "U1.1", "to": null, "gap_pixels": 15, "severity": "error"}
  ],
  "label_issues": [
    {"label": "VCC", "position": "valid/floating/missing"}
  ],
  "component_issues": [],
  "overall_status": "pass/warning/fail"
}
```

## 修复策略

### 连接问题修复
- 端点未到达: 重新计算连线终点坐标
- 悬空连线: 检查是否需要删除或补全连接
- 网络标签位置错误: 调整标签坐标

### 封装问题修复
- 符号-封装不匹配: 更新封装映射
- 引脚-焊盘不对应: 修正引脚映射表

### 布局问题修复
- 间距过小: 调整元件位置
- 走线锐角: 重新布线

## 质量标准

| 级别 | 数据层 | 规则层 | 视觉层 | 语义层 | 发布条件 |
|------|--------|--------|--------|--------|----------|
| P0 | 100% | 100% | 100% | 90% | 必须通过 |
| P1 | 100% | 100% | 95% | 85% | 建议通过 |

## 开始执行

请立即开始第一次迭代:
1. 创建必要的目录结构
2. 生成截图
3. 执行4层验证
4. 生成初始问题.md
5. 开始修复
```
